PERSISTENT MULTI-STREAM LATENT WORLD STATE

Beyond Token Time.

Language is an interface. The question is whether the same serialized token stream should also determine how an intelligent system computes, remembers, and reacts.

Keep a persistent internal state. Update only what an event changes. Serialize to a modality only when interaction requires it. And when more internal computation is needed, let the model continue in continuous space without being forced to commit to another word.

01 / START WITH THE BOTTLENECK

One token becomes one step.

An autoregressive LLM carries a continuous hidden state internally, turns that state into a probability distribution over tokens, chooses a token, appends it to the context, and runs again.

continuous hidden state -> token -> next hidden state

Here, hidden state means the model's current continuous internal representation. A token is the discrete symbol exposed to the language interface. This creates a very simple clock: each emitted token advances the visible sequence by one step.

That clock is natural for writing. It is less obviously necessary for internal computation.

The first relaxation: do not emit a word every time

Coconut provides an important proof of possibility. Some reasoning steps can remain in the model's continuous representation instead of being decoded into language first. The hidden representation can be fed back into the next computation directly.

Latent continuationIn this note, latent means an internal continuous representation that has not yet been serialized into text, speech, pixels, or another external modality.

This removes one constraint: internal computation can continue without speaking at every step. But it leaves a second question. What is the smallest change that turns the already-successful token reasoning loop into a continuous one?

Chain-of-thought was already a recurrent computation

Explicit chain-of-thought can be viewed as an unusually stable form of adaptive computation. The model emits an intermediate symbol, the symbol is embedded again, and the same transformer is called for another step. The number of reasoning steps is not fixed in the architecture; it is expressed as the length of the generated trace.

h_t -> reasoning token -> E(token) -> Transformer -> h_{t+1}

In that sense, CoT is a recurrent loop with a discrete semantic bottleneck. Supervised expert traces made the loop easy to bootstrap: the model could learn variable-length computation by imitating a readable sequence. Once a model already possesses strong reasoning behavior, the next architectural question is whether that bottleneck can be relaxed without discarding the stable autoregressive machinery that made CoT work.

02 / A MINIMAL CONTINUOUS RECURRENCE

Emit a null token. Carry the latent state instead.

The proposed mechanism does not add a vertical recurrent block to the transformer. It keeps the ordinary autoregressive decode loop and adds one control action: a silent or null token.

Let the LM head select either a normal token or a reserved internal token <NULL>. When a normal token is selected, generation behaves as usual. When <NULL> is selected, nothing is serialized to the user. Instead, the next input is the null-token embedding mixed with a gated continuous vector from the previous reasoning step.

z_t = P(h_t),   g_t = sigmoid(W_g h_t)
x_{t+1} = E(y_t) + 1[y_t = NULL] · g_t ⊙ z_t

The transformer then runs normally again. Repeated null emissions therefore create additional unrolled depth along the generation axis. The model chooses when to keep thinking by emitting another null token and when to re-enter the visible token stream by emitting a normal token.

The recurrence is in the decode loop, not a separate vertical stack. A run such as Q → NULL → NULL → NULL → A spends four transformer passes before committing to the answer token.

Fixed depth and variable depth are different claims

If the number of silent passes is fixed, the mechanism is functionally close to adding more unrolled depth with tied weights. The more interesting regime is variable recurrence: the model learns how many silent steps a particular state needs. That turns loop count into an action, close in spirit to adaptive computation time, but implemented through the existing autoregressive scheduler.

Reinforcement learning is a natural stage for learning this policy because there is usually no unique target for either the latent trajectory or the correct number of silent steps. A simple objective can reward task success while charging for unnecessary recurrence. Supervised or distilled variants are also possible if latent-step targets are constructed; RL is not mathematically required, but it avoids having to label an invisible trace.

reward = task quality − λ · (# NULL steps) − stability / safety penalties

The gate can make the mechanism more general

The minimal version activates continuous carry only after a null token. A more general version can make the latent mix-in always available and let the gate learn when it should be near zero:

x_{t+1} = E(y_t) + g_t ⊙ z_t

This turns the discrete token into an interface signal rather than the sole carrier of state. A visible token can still anchor the sequence semantically, while the continuous side channel preserves information that would otherwise have to be quantized into language.

From one latent carry to several channels

Nothing restricts the carried state to one vector. With persistent components z_t^(1)...z_t^(K), a controller can mix several latent channels into the next computation:

x_{t+1} = E(y_t) + Σk g_t(k) ⊙ P_k(z_t(k))

That is where continuous reasoning becomes qualitatively different from a single textual CoT. A token stream can serialize only one sequence of commitments. A continuous state can simultaneously maintain a visual hypothesis, a linguistic interpretation, a plan, several candidate explanations, or other latent processes before any one of them must become text.

Implementation surface versus implementation workConceptually, an inference API could expose this as one option such as continuous_reasoning=true plus a reserved control token. Underneath, the runtime still needs per-sequence latent side state, dynamic input-embedding injection, KV-cache updates for silent steps, batching rules, and a sampler that suppresses null tokens from the user-visible stream. The conceptual modification is small; the serving change is not literally one line.

Astra: a hypothesis, not an attribution

Public reporting in The Information describes OpenAI's Astra as using recurrent depth or a looped transformer, repeatedly processing information before emitting the next word, and says OpenAI limits the use of the technique so a legible chain of thought remains available. OpenAI's own public material says Astra will use additional chain-of-thought monitoring, but does not disclose this architectural mechanism.

OpenAI Chief Scientist Jakub Pachocki also stated publicly that the computation-graph depth of current frontier models, including Astra, is within a factor of two of GPT-4, and that declining CoT monitorability is driven by factors that are not contingent on architecture changes. That is important evidence against reading the reporting too literally.

Our architectural hypothesisThe null-token + gated-latent mechanism above is our proposed implementation. It is one minimal way to obtain functionally similar unrolled recurrent computation while preserving the ordinary token-generation loop. It may be equivalent or closely related in behavior to what has been reported about Astra, but there is currently no public evidence that Astra uses this exact mechanism.

Why monitorability becomes a first-class problem

Text CoT is unusual because the computational loop and the human-readable trace are partially aligned: each extra reasoning step tends to leave another visible symbol. Once several transformer passes can occur behind null emissions or continuous carry, that alignment disappears. The visible answer may expose only occasional checkpoints of a much richer latent computation.

This does not mean latent recurrence alone causes the monitorability trend. Pachocki explicitly cautions otherwise. It means that once reasoning can happen without serialization, readability is no longer an automatic by-product of the computation architecture. If monitoring is important, it has to be deliberately trained, probed, or reconstructed.

03 / FROM ONE CHAIN TO SEVERAL EVOLVING PARTS

A world contains more than one thing at a time.

Consider a full-duplex assistant. While it is speaking, new audio can arrive, the speaker's intent can change, the response plan can evolve, and objects in the scene can keep moving.

A video model gives an even simpler picture. One frame may contain several people, a moving car, changing light, camera motion, and an occluded object. The video is one serialized output, but the represented world is not one process.

Audio-video generation makes the multi-stream requirement more concrete. To generate a conversation between two actors, one model must preserve actor identity, per-actor motion, turn-taking, voice-to-character binding, lip synchronization, camera motion, and shared scene state over the same timeline. This is strong behavioral evidence of multi-stream capability, even if the implementation does not expose explicit latent stream slots.

These pieces do not need to change at the same moment. A speaker state may update when a new utterance arrives. A tracked object may update when the camera sees motion. A plan may update only when new evidence matters.

What "stream" means hereA stream is one separately evolving component of internal state. Multiple streams do not mean multiple models or multiple textual chains. They mean several coordinated components inside one world state: the model's current representation of what exists, what is changing, and what may happen next.
STREAM EXAMPLE

A candidate course of action that may change independently of speech.

The proposed move is therefore not "generate many chains of thought." It is to let several parts of one internal world state evolve without forcing all of them through the same token sequence.

04 / MODALITIES AS LENSES

The world does not arrive in one native format.

Text, images, audio, and sensor readings are different sampled views of the same underlying reality.

An RGB camera captures selected electromagnetic wavelengths. A microphone samples pressure changes. Korean and English encode events with different symbol systems. Other animals sense different spectra again. None of these interfaces has a privileged claim to be the native format of intelligence.

observation in modality m = lens_m(world state)

This leads to a second design principle: the modality used for training or communication should not unnecessarily determine the format of internal computation.

Modalities are lenses on the world. They do not have to be the place where the world model lives.

05 / ARCHITECTURE

A persistent state, changed by events.

With latent state and streams defined, the architecture becomes straightforward: keep a persistent internal state, route each new event to the parts it affects, and serialize only when an external interface needs output.

One more term: eventAn event is anything that makes some part of the internal state worth updating: a new audio segment, visible motion, an interruption, a tool result, a memory retrieval, or an internal reasoning trigger. A null-token reasoning step is one possible internal event.

Write the persistent state as Z = {z1, z2, ..., zK}. Each component can carry a different piece of the current world model. When an event arrives, only the relevant components need to change.

For example, a new sound might update speaker identity, semantic interpretation, and dialogue state. A suddenly visible obstacle might update perception, control, and planning. Nothing about either event requires every internal component to advance because a text token was emitted.

Delayed commitment

The same structure can preserve uncertainty. If several hypotheses remain plausible, they can remain distinct components of the evolving state until later evidence changes their relative importance. The claim is not that a continuous vector contains unlimited information. The narrower claim is that a discrete token imposes a particular quantization and semantic commitment, and sometimes that commitment happens earlier than necessary.

06 / THREE CLOCKS

Token time, compute time, and world time are different.

Once events can update only the state they affect, a single token counter no longer has to serve as the clock for everything.

CLOCK 1

Token time

Advances when an external discrete sequence emits another visible symbol.

CLOCK 2

Compute time

Advances whenever internal state performs another update, including a silent recurrent pass.

CLOCK 3

World time

Advances as relevant external events occur.

token time != compute time != world time

Null-token recurrence makes the distinction explicit. A sequence can spend several compute steps while visible token time stands still. Meanwhile, vision, audio, or tool events may advance according to the world rather than according to either counter.

Event time also needs a reproducible order. If one event can causally affect another, that precedence must be preserved. If two events are causally unrelated, their order is not universal; chronology must be attributed to a declared observer and reference frame.

Proper time or coordinate time?Proper time can order local receipt events along one observer's worldline. It does not by itself order remote events that occurred at different locations. Those events need coordinate time in the selected reference frame. A practical event bus can then sort by frame-relative occurrence time, local receipt time, and a stable event ID, without treating chronological order as causation.
07 / PRIOR WORK

What is already known, and what remains open.

Several pieces of this picture already exist. The point is not to rename them, but to identify the remaining architectural gap.

WorkWhat it establishesWhat remains open here
CoconutReasoning can continue in continuous hidden state without decoding every step into language; latent alternatives can be preserved.Can this become a general recurrent interface attached to the ordinary decode loop and persist across perception, reasoning, and action?
Perceiver IOA shared latent representation can mediate heterogeneous inputs and outputs.Can the state persist across events and update selectively over time rather than mainly serve a read-process-write pass?
Hybrid Latent Reasoning via RLRL can optimize policies that move between latent and discrete reasoning.Can outcome-driven training learn when to emit a silent step, how much latent state to carry, and which persistent components to update?
Parallel latent test-time scalingSeveral continuous reasoning trajectories can be sampled and compared.Can simultaneous latent components represent entities, goals, sensor processes, or hypotheses inside one world state rather than separate answer rollouts?
Multi-Stream LLMsSeveral token streams can read and write concurrently.Do internal streams need to be tokens at all, or share the same update clock?
Looped / recurrent-depth TransformersRepeated application of shared transformer blocks can increase effective depth and support implicit reasoning or depth extrapolation.Can recurrence be controlled through an autoregressive null action and coupled to persistent multi-stream state without requiring a separately exposed recurrent stack?

The resulting claim is deliberately narrow:

General-purpose intelligence may benefit from a persistent, structured set of latent state components whose updates are triggered asynchronously by relevant events, with silent continuous recurrence available when more computation is needed and serialization delayed until an interface requires it.
08 / FALSIFIABLE TESTS

Try to break the idea before scaling it.

The first useful experiment should be small enough that the architectural difference is visible and compute can be matched.

text CoT | fixed recurrent depth | variable NULL recurrence | asynchronous multi-stream latent
Null-token recurrence under matched compute

Compare explicit CoT, a fixed number of tied recurrent passes, and learned variable null-token passes. Match total transformer FLOPs. Measure task accuracy, latency, number of visible tokens, and number of silent steps.

Gate ablation

Compare token-only input, null embedding only, ungated latent carry, gated latent carry, and always-on gated carry. Test whether the continuous vector carries useful state rather than merely acting as extra depth.

Monitorability probe

Train probes or auxiliary decoders to reconstruct intermediate reasoning concepts from silent states. Measure how decodability changes as null-step budget increases, and whether explicit CoT checkpoints can preserve oversight without forcing every computation through text.

Asynchronous multi-entity world

Several entities change on different schedules. Measure tracking accuracy, cross-state interference, FLOPs, memory, and latency as the number of independently evolving entities rises.

Delayed evidence

Early observations support several hypotheses; later evidence resolves them. Measure revision cost and recovery after contradictory evidence.

Interruption

The model starts speaking or acting and receives new information before it finishes. Measure reaction latency and how much prior continuous computation can be reused.

Cross-modal action without text

Provide vision and audio input and require a non-linguistic action. Test whether an intermediate textual serialization adds value or only delay.

Killer ablationIf variable null-token recurrence does not outperform a compute-matched combination of explicit CoT and fixed-depth baselines, or if the latent carry can be removed without loss, the mechanism is not justified. If asynchronous structured state does not beat simpler sequential or parallel baselines on independent-clock and interruption tasks, the broader architecture is not justified either.
