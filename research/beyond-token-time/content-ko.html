REPRESENTATION BEYOND INTERFACE BOTTLENECKS

토큰 시간 너머.

모델의 표현 공간은 우리가 모델과 주고받는 인터페이스보다 훨씬 넓다. 문제는 이 넓은 공간이 token, 하나의 시간축, 하나의 stream, 그리고 modality라는 몇 가지 익숙한 형식으로 계속 압축된다는 데 있다.

핵심 가설은 새로운 hidden-thinking 기법 하나가 아니다. 지능의 내부 표현과 외부 인터페이스를 분리하고, 필요할 때만 discrete token·fixed clock·named modality로 투영하는 것이 더 자연스러운 계산 구조일 수 있다는 것이다.

01 / THE THESIS

표현 공간보다 인터페이스가 더 좁다.

Transformer는 매 layer에서 수천 차원의 continuous vector를 계산합니다. 여러 feature와 hypothesis가 동시에 존재할 수 있고, 한 vector가 하나의 단어나 하나의 modality에만 대응할 이유도 없습니다. 그런데 다음 step으로 넘어가는 순간 이 상태는 몇 가지 강한 제약을 통과합니다.

rich continuous state → interface bottleneck → next computation

현재 LLM의 성공은 이 bottleneck이 나빴다는 뜻이 아닙니다. 오히려 tokenization과 autoregressive decoding은 대규모 학습을 가능하게 한 매우 좋은 scaffold였습니다. 다만 학습을 가능하게 한 scaffold가 지능의 최종 계산 형식이어야 할 이유는 없습니다.

Beyond Token Time의 범위여기서 "token"은 단어 조각 하나만을 뜻하지 않습니다. 내부 표현을 외부에서 다루기 쉬운 discrete symbol로 바꾸는 과정 전체를 가리킵니다. "time"도 wall-clock time만 뜻하지 않습니다. 모든 계산이 하나의 고정된 step counter를 따라야 한다는 가정을 뜻합니다.
02 / ONE PATTERN, FOUR BOTTLENECKS

Token, time, modality, seriality는 같은 종류의 제약일 수 있다.

겉으로는 서로 다른 문제처럼 보이지만, 네 가지 모두 넓은 내부 표현을 특정 인터페이스 좌표계에 맞춰 projection한다는 공통점이 있습니다.

BOTTLENECK 1

Discrete token

Continuous state를 vocabulary의 한 symbol로 quantize하고 semantic commitment를 강제합니다.

BOTTLENECK 2

Fixed clock

모든 추가 계산이 token position 또는 고정 depth와 같은 하나의 cadence를 따라가게 합니다.

BOTTLENECK 3

Named modality

Text, image, audio를 서로 다른 mode처럼 취급해 내부 표현도 그 경계를 따라야 하는 것처럼 보이게 합니다.

BOTTLENECK 4

Single serial stream

여러 entity, hypothesis, plan이 동시에 존재해도 하나의 순서로 serialize하게 합니다.

CONSEQUENCE

Early commitment

아직 열려 있어도 되는 선택을 너무 일찍 token, order, modality, one-stream representation으로 고정합니다.

RELAXATION

Interface on demand

내부 state는 더 자유롭게 유지하고, 실제 interaction이 요구할 때만 필요한 형식으로 읽어냅니다.

representation ≠ serialization ≠ schedule ≠ modality
03 / TOKEN IS A USEFUL QUANTIZER

CoT는 adaptive compute를 안정적으로 발견한 방법이었다.

Explicit chain-of-thought를 다시 보면, token은 reasoning의 내용인 동시에 recurrent state carrier 역할을 합니다.

h_t → reasoning token → E(token) → Transformer → h_{t+1}

이 구조의 장점은 엄청납니다. Expert trace를 supervised target으로 쓸 수 있고, reasoning step 수를 trace 길이로 표현할 수 있습니다. 별도의 halting controller 없이도 variable-depth compute가 가능해집니다. 그런 의미에서 CoT는 가장 안정적으로 학습된 adaptive computation 중 하나였습니다.

하지만 비용도 명확합니다. 다음 계산으로 넘길 상태가 반드시 human language의 discrete semantic unit을 통과해야 합니다. 여러 candidate가 동시에 살아 있거나 image·audio·plan feature가 함께 존재하더라도, feedback path는 결국 하나의 token embedding으로 좁아집니다.

문제는 token이 아니라 exclusivity다Token은 훌륭한 interface입니다. 문제는 token이 internal recurrence의 유일한 feedback channel이 되는 순간입니다. "token을 없애자"가 아니라 "token만 있어야 하는가"가 더 정확한 질문입니다.
04 / TIME IS ALSO AN INTERFACE

왜 모든 계산이 같은 시계로 움직여야 할까.

현재 모델에서는 서로 다른 종류의 시간이 자주 하나로 합쳐집니다. Token을 하나 더 생성하는 것, transformer를 한 번 더 계산하는 것, 세계에서 사건이 하나 더 일어나는 것이 같은 step처럼 취급됩니다.

CLOCK 1

Token time

Visible symbol이 하나 늘어날 때 전진합니다.

CLOCK 2

Compute time

내부 state가 추가 계산을 할 때 전진합니다.

CLOCK 3

World time

외부의 관련 event가 발생할 때 전진합니다.

token time ≠ compute time ≠ world time

쉬운 문제는 한 번 계산하고 끝날 수 있고, 어려운 문제는 같은 visible position에서 여러 번 계산할 수 있습니다. 대화 중에는 speech generation이 진행되는 동안 audio input이 들어올 수 있고, vision은 또 다른 cadence로 갱신될 수 있습니다. Fixed timing은 구현에는 편하지만 지능의 intrinsic time이라고 보기는 어렵습니다.

따라서 "Beyond Token Time"은 단순히 token 없이 생각한다는 뜻이 아닙니다. 계산에 필요한 시간을 token sequence가 독점하지 않게 한다는 뜻에 더 가깝습니다.

05 / MODALITY IS A LENS

Text, image, audio는 세계의 서로 다른 관측 방식이다.

Modality는 모델 안에 존재하는 ontological category라기보다, 어떤 현실을 어떤 sensor와 sampling rule로 관측했는지에 가깝습니다.

observation in modality m = lens_m(world state)

RGB camera는 특정 파장과 해상도로 세계를 sampling하고, microphone은 압력 변화를 sampling합니다. 한국어와 영어는 같은 사건을 서로 다른 symbol system으로 encode합니다. 이 관점에서는 text/image/audio가 서로 다른 "지능 mode"라기보다 하나의 underlying state를 보는 다른 lens입니다.

현재 multimodal architecture는 실용적으로 modality별 encoder, tokenizer, decoder를 분리합니다. 필요한 engineering입니다. 하지만 이 경계가 internal representation의 자연스러운 경계라고 오해하면 문제가 생깁니다. 내부적으로는 한 object의 모양, 이름, 소리, motion, affordance가 하나의 상태에서 결합되는 편이 더 자연스러울 수 있습니다.

Modality-agnostic의 의미모든 sensor를 같은 tokenizer에 넣자는 뜻이 아닙니다. Input/output adapter는 달라도 되지만, 내부 world representation이 adapter의 형식에 종속될 필요는 없다는 뜻입니다.
06 / THE WORLD IS NOT A SINGLE STREAM

하나의 출력 sequence가 하나의 process를 뜻하지는 않는다.

한 video frame 안에는 여러 object가 동시에 있고, 한 대화 장면에서는 여러 actor의 identity, voice, gaze, turn-taking, camera motion이 함께 유지됩니다. Output은 하나의 timeline이지만 represented world는 하나의 chain이 아닙니다.

Text CoT도 비슷합니다. "첫 번째 가설을 생각한 뒤 두 번째 가설을 생각한다"고 써야 하지만, 내부에서는 두 가설의 evidence가 동시에 유지될 수 있습니다. 하나의 serial trace는 설명하기에는 좋지만, state 자체의 필수 형식일 필요는 없습니다.

one output stream ≠ one internal process

이 때문에 persistent multi-stream latent state가 중요해집니다. Stream은 여러 모델을 뜻하지 않습니다. Entity, hypothesis, plan, dialogue state처럼 서로 다른 cadence로 갱신될 수 있는 state component를 뜻합니다.

Tokens are interfaces. Modalities are lenses. Time is a schedule. None of them has to be the native format of thought.
08 / CONCRETE RELAXATIONS

Null-token recurrence는 전체 아이디어를 구현하는 한 가지 작은 해법이다.

v1.1에서 강조했던 null-token + gated latent는 여기서 더 정확한 위치를 가집니다. 전체 architecture 자체가 아니라, token bottleneck과 token-time coupling을 동시에 느슨하게 만드는 최소 구현입니다.

LM head에 내부용 <NULL> action을 하나 두고, null이 선택되면 user-visible token은 내보내지 않습니다. 대신 다음 input에 null embedding과 직전 continuous state를 gate해서 섞습니다.

이 방식은 별도의 세로 recurrent block을 요구하지 않습니다. 기존 autoregressive loop에서 visible token time을 멈춘 채 compute time만 추가로 진행합니다.

이 primitive를 multi-stream state와 결합하면 한 vector만 carry할 필요도 없습니다. 여러 component의 gated mixture를 다음 계산에 넣을 수 있습니다.

x_{t+1}=E(y_t)+Σ_k g_t^(k)⊙P_k(z_t^(k))

Astra와의 관계

공개 보도는 Astra에 recurrent depth 또는 looped transformer가 사용된다고 설명하지만 정확한 architecture는 공개되지 않았습니다. 따라서 위 구현은 Astra에 대한 attribution이 아니라, 보도된 동작과 기능적으로 유사한 recurrence를 기존 decode loop에서 구현할 수 있는 독립적인 architecture hypothesis로 다룹니다.

Monitorability

이 구현의 중요한 trade-off도 여기서 자연스럽게 보입니다. Text CoT는 internal compute와 human-readable trace를 우연히 같은 channel에 올려놓았습니다. Continuous recurrence가 가능해지면 그 정렬은 사라집니다. 따라서 monitorability는 자동으로 따라오는 성질이 아니라 별도로 설계해야 할 objective가 됩니다. 이것은 null-token만의 문제가 아니라, 더 넓은 representation space를 interface bottleneck에서 해방할 때 공통으로 생기는 문제입니다.

09 / FALSIFIABLE TESTS

해방된 표현 공간이 실제로 가치가 있는지 검증해야 한다.

"더 continuous하면 더 좋다"는 주장은 충분하지 않습니다. 각 bottleneck을 하나씩 풀었을 때 compute-matched baseline보다 실제 이득이 있어야 합니다.

Discrete bottleneck

Explicit CoT와 null-token latent carry를 같은 FLOPs에서 비교하고, latent carry를 제거했을 때 성능이 유지되는지 확인합니다.

Time bottleneck

Fixed recurrent depth와 learned variable recurrence를 비교해 task difficulty에 따라 compute allocation이 실제 달라지는지 측정합니다.

Modality bottleneck

동일 사건의 text/image/audio 관측을 서로 다른 adapter로 넣되 shared latent state의 cross-modal consistency와 direct action 성능을 측정합니다.

Seriality bottleneck

여러 entity/hypothesis가 독립적으로 변하는 task에서 single-state baseline과 persistent component state를 matched compute로 비교합니다.

Monitorability cost

표현 자유도가 커질수록 probe decodability, intervention predictability, sparse verbal checkpoint의 fidelity가 어떻게 변하는지 측정합니다.

Killer testToken·time·modality·seriality bottleneck을 완화해도 matched compute에서 성능, 효율, robustness, interruption handling 중 의미 있는 이득이 없다면 더 복잡한 latent architecture는 정당화되지 않습니다.
10 / PAPER
