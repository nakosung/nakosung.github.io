PERSISTENT MULTI-STREAM LATENT WORLD STATE

토큰 시간 너머.

언어는 인터페이스다. 문제는 같은 직렬 token stream이 지능의 계산, 기억, 반응 방식까지 결정해야 하느냐는 것이다.

Persistent internal state를 유지하고, event가 바꾼 부분만 갱신하며, 상호작용이 필요할 때만 modality로 serialize한다. 그리고 내부 계산이 더 필요할 때는 다음 단어로 억지로 commit하지 않고 continuous space에서 계산을 이어가게 한다.

01 / 먼저 병목부터

토큰 하나가 계산의 한 스텝이 된다.

Autoregressive LLM은 내부에 연속적인 hidden state를 가지고 있다가, 그 상태를 token 확률분포로 바꾸고 하나를 선택해 context에 붙인 뒤 다시 계산합니다.

continuous hidden state -> token -> next hidden state

여기서 hidden state는 모델이 현재 가지고 있는 연속적인 내부 표현을 뜻합니다. token은 언어 인터페이스로 드러나는 discrete symbol입니다. 이 구조에서는 아주 단순한 clock이 생깁니다. token 하나를 내보낼 때마다 visible sequence가 한 칸 앞으로 갑니다.

글을 생성할 때는 자연스러운 clock입니다. 하지만 내부 계산까지 반드시 이 clock에 맞춰야 하는지는 별개의 문제입니다.

첫 번째 완화: 매번 단어를 내보내지 않아도 된다

Coconut은 중요한 가능성을 실제로 보여줍니다. Reasoning의 일부 step을 먼저 언어로 decode하지 않고, 모델 내부의 연속적인 표현 상태로 그대로 다음 계산에 넘길 수 있습니다.

Latent continuation여기서 latent는 아직 text, speech, pixel 같은 외부 modality로 serialize되지 않은 내부의 연속 표현을 뜻합니다.

이렇게 하면 하나의 제약은 사라집니다. 내부 계산이 매 step마다 말을 할 필요는 없습니다. 그러면 다음 질문은 더 구체적입니다. 이미 잘 작동하는 token reasoning loop를 버리지 않고, 가장 작은 변경으로 continuous loop로 바꿀 수 있을까요?

Chain-of-thought도 결국 recurrent computation이었다

Explicit CoT를 다시 보면, 사실 굉장히 안정적으로 구현된 adaptive computation이라고 볼 수 있습니다. 모델이 중간 symbol을 하나 내고, 그 symbol이 다시 embedding되어 같은 transformer가 다음 step을 계산합니다. Reasoning step 수는 architecture에 고정되어 있지 않고 생성된 trace 길이로 표현됩니다.

h_t -> reasoning token -> E(token) -> Transformer -> h_{t+1}

이 관점에서 CoT는 discrete semantic bottleneck을 가진 recurrent loop입니다. Expert trace를 이용한 supervised training은 variable-length computation을 아주 안정적으로 bootstrap하는 방법이었습니다. 모델이 이미 reasoning capability를 충분히 가진 다음에는, 이 loop 자체를 없애기보다 중간의 discrete bottleneck만 완화하는 것이 자연스러운 다음 단계일 수 있습니다.

02 / 가장 작은 CONTINUOUS RECURRENCE

Null token을 emit하고, latent state를 다음 입력으로 넘긴다.

여기서 제안하는 방식은 transformer 안에 세로 방향의 recurrent block을 새로 만드는 것이 아닙니다. 기존 autoregressive decode loop를 그대로 두고, control action 하나만 추가합니다. 바로 silent/null token입니다.

LM head가 일반 token 또는 내부용 reserved token <NULL>을 선택하게 합니다. 일반 token이면 지금과 똑같이 동작합니다. <NULL>이면 사용자에게는 아무것도 serialize하지 않고, 다음 model input에 null-token embedding과 직전 reasoning step의 continuous vector를 gate해서 섞어 넣습니다.

z_t = P(h_t),   g_t = sigmoid(W_g h_t)
x_{t+1} = E(y_t) + 1[y_t = NULL] · g_t ⊙ z_t

그 다음에는 같은 Transformer N layers를 다시 통과하면 됩니다. Null token이 연속해서 나오면 generation 축을 따라 추가 depth가 unroll됩니다. 모델이 계속 생각하고 싶으면 다시 null을 emit하고, visible stream으로 돌아오고 싶으면 일반 token을 emit합니다.

Recurrence는 별도의 세로 stack이 아니라 기존 decode loop에 있습니다. 예를 들어 Q → NULL → NULL → NULL → A라면 답 token으로 commit하기 전에 같은 transformer를 네 번 통과하며 계산한 것입니다.

Fixed depth와 variable depth는 다른 주장이다

Silent pass 수를 항상 고정한다면, 기능적으로는 tied weight를 가진 추가 unrolled depth와 상당히 비슷합니다. 더 흥미로운 경우는 variable recurrence입니다. 현재 state가 얼마나 더 계산을 필요로 하는지를 모델이 스스로 결정합니다. Loop count 자체가 action이 되며, adaptive computation time과 비슷한 효과를 기존 autoregressive scheduler 위에서 구현할 수 있습니다.

이 policy를 학습하는 데 RL이 자연스럽습니다. Latent trajectory에도, null step 수에도 정답 trace가 하나로 정해져 있지 않기 때문입니다. Task reward를 주고 불필요한 recurrence에 비용을 부과하면 됩니다. 물론 latent target이나 teacher trajectory를 인위적으로 만들 수 있다면 supervised/distillation 방식도 가능합니다. 즉 RL만 수학적으로 가능한 것은 아니지만, invisible trace를 label하지 않고 variable loop를 배우기에는 RL이 가장 자연스럽습니다.

reward = task quality − λ · (# NULL steps) − stability / safety penalties

Gate를 두면 더 일반적인 형태가 된다

가장 단순한 버전은 null token일 때만 continuous carry를 켭니다. 더 일반적으로는 mix-in을 항상 열어두고 gate가 필요 없을 때 0에 가깝게 만들도록 학습할 수도 있습니다.

x_{t+1} = E(y_t) + g_t ⊙ z_t

그러면 discrete token은 state 전체를 운반하는 유일한 매체가 아니라 interface signal이 됩니다. Visible token은 sequence의 semantic anchor 역할을 하고, continuous side channel은 언어로 quantize할 필요가 없는 정보를 유지합니다.

한 개의 latent carry에서 여러 channel로

넘기는 state가 하나의 vector일 이유도 없습니다. Persistent component를 z_t^(1)...z_t^(K)로 두고 controller가 여러 latent channel을 다음 계산에 mix할 수 있습니다.

x_{t+1} = E(y_t) + Σk g_t(k) ⊙ P_k(z_t(k))

여기서 continuous reasoning은 single textual CoT와 질적으로 달라집니다. Token stream은 결국 하나의 commitment sequence만 serialize합니다. Continuous state는 text로 하나를 고르기 전에 visual hypothesis, linguistic interpretation, plan, 여러 explanation candidate, sensor state 등을 동시에 유지할 수 있습니다.

API surface는 작아도 serving 구현은 한 줄이 아니다개념적으로는 inference API에 continuous_reasoning=true 같은 option과 reserved control token 하나를 추가하는 형태로 보일 수 있습니다. 하지만 runtime 내부에서는 sequence별 latent side state, 매 decode step의 dynamic input embedding injection, silent step의 KV-cache update, batching/scheduling, null token을 user-visible stream에서 숨기는 sampler 처리가 필요합니다. Conceptual modification은 작지만 실제 vLLM 변경이 literally 한 줄이라는 뜻은 아닙니다.

Astra와의 관계: attribution이 아니라 architecture hypothesis

The Information의 공개 보도는 OpenAI의 Astra가 recurrent depth 또는 looped transformer를 사용하며, 다음 word를 내기 전에 같은 정보를 반복 처리한다고 설명합니다. 또 OpenAI가 legible CoT를 유지하기 위해 이 기법의 사용을 제한했다고 보도합니다. 반면 OpenAI의 공식 공개 자료는 Astra에 추가 CoT monitoring을 적용한다고 밝히지만 이 architecture를 직접 공개하지는 않았습니다.

OpenAI Chief Scientist Jakub Pachocki는 공개 글에서 Astra를 포함한 현 frontier model들의 computation graph depth가 GPT-4의 2배 이내이며, CoT monitorability가 나빠지는 이유는 architecture change에 의존하지 않는다고 덧붙였습니다. 따라서 보도를 너무 직접적으로 architecture 사실로 해석하면 안 됩니다.

Architecture hypothesis위의 null-token + gated latent 방식은 여기서 제안하는 구현입니다. 기존 token generation loop를 유지하면서 functionally similar한 unrolled recurrent computation을 만드는 가장 단순한 후보 중 하나입니다. 보도된 Astra의 동작과 equivalent하거나 closely related할 가능성을 추정할 수는 있지만, Astra가 이 exact mechanism을 쓴다는 공개 근거는 현재 없습니다.

왜 monitorability가 별도의 문제가 되는가

Text CoT가 특별했던 이유는 computational loop와 human-readable trace가 어느 정도 정렬되어 있었기 때문입니다. 추가 reasoning step이 생기면 대체로 visible symbol도 하나 더 남았습니다. Null emission이나 continuous carry 뒤에서 transformer pass가 여러 번 일어나기 시작하면 이 정렬이 깨집니다. Visible answer는 훨씬 풍부한 latent computation의 checkpoint 몇 개만 보여줄 수 있습니다.

그렇다고 latent recurrence가 현재 monitorability 저하의 원인이라고 단정할 수는 없습니다. Pachocki도 architecture와 무관한 원인이 있다고 명시했습니다. 더 정확한 결론은 이겁니다. Reasoning이 serialization 없이 진행될 수 있게 되는 순간, readability는 computation architecture가 자동으로 주는 부산물이 아니다. 필요하다면 monitorability 자체를 별도의 학습 목표, probe, reconstruction 문제로 설계해야 합니다.

03 / 하나의 CHAIN에서 여러 변화 요소로

세계에는 한 순간에도 여러 일이 함께 존재한다.

Full-duplex assistant를 생각해 보면 쉽습니다. 답을 말하는 동안에도 새 음성이 들어오고, 상대의 의도가 바뀔 수 있고, response plan이 수정될 수 있고, 카메라 속 물체는 계속 움직입니다.

Video model은 더 직관적인 예입니다. 한 frame 안에 여러 사람, 움직이는 자동차, 조명의 변화, camera motion, 가려진 물체가 동시에 있을 수 있습니다. Video output은 한 줄의 시간축으로 serialize되지만, 그 안의 세계가 하나의 process인 것은 아닙니다.

Audio-video generation은 multi-stream requirement를 더 직접적으로 보여줍니다. 두 actor의 대화를 하나의 모델이 생성하려면 actor identity, 각 actor의 motion, turn-taking, voice-to-character binding, lip sync, camera motion, shared scene state를 같은 timeline에서 함께 유지해야 합니다. 구현 내부에 명시적인 latent stream slot이 보이지 않더라도, 기능 수준에서는 강한 multi-stream capability입니다.

이 요소들은 같은 순간에 바뀔 필요도 없습니다. Speaker state는 새 발화가 들어올 때 바뀌고, object state는 motion이 관측될 때 바뀌며, plan은 새로운 evidence가 의미 있을 때만 갱신될 수 있습니다.

여기서 말하는 streamStream은 내부 state 중에서 독립적인 속도로 변화할 수 있는 하나의 구성요소를 뜻합니다. Multiple streams는 여러 모델이나 여러 textual chain을 뜻하지 않습니다. 하나의 world state 안에서 여러 구성요소가 함께 유지되고 서로 영향을 주는 구조를 뜻합니다. 여기서 world state는 현재 무엇이 존재하고, 무엇이 변하고 있으며, 무엇이 다음에 일어날 수 있는지에 대한 내부 표현입니다.

04 / MODALITY는 LENS

세계는 하나의 native format으로 들어오지 않는다.

Text, image, audio, sensor reading은 같은 현실을 서로 다른 방식으로 sampling한 관측입니다.

RGB camera는 특정 전자기파 영역을 잡고, microphone은 공기 압력 변화를 sampling합니다. 한국어와 영어는 같은 사건을 서로 다른 symbol system으로 기록합니다. 다른 생물은 또 다른 spectrum을 봅니다. 어느 modality도 지능의 원래 포맷이라고 볼 특별한 이유는 없습니다.

observation in modality m = lens_m(world state)

여기서 두 번째 설계 원칙이 나옵니다. 학습이나 커뮤니케이션에 쓰인 modality가 내부 계산 형식까지 결정할 필요는 없습니다.

Modality는 세계를 보는 lens다. World model 자체가 그 lens 안에 갇힐 필요는 없다.

05 / ARCHITECTURE

State는 유지하고, event가 바뀐 부분만 갱신한다.

Latent와 stream의 의미를 먼저 정했으니 구조는 단순해집니다. Persistent internal state를 유지하고, 새 event가 들어오면 영향을 받는 부분만 갱신하고, 외부 인터페이스가 필요할 때만 serialize합니다.

Persistent state를 Z = {z1, z2, ..., zK}라고 쓰겠습니다. 각 component는 현재 world model의 서로 다른 부분을 담을 수 있습니다. Event가 들어오면 관련 component만 바뀌면 됩니다.

예를 들어 새로운 소리는 speaker identity, semantic interpretation, dialogue state를 갱신할 수 있습니다. 갑자기 나타난 장애물은 perception, control, planning을 갱신할 수 있습니다. 어느 경우에도 text token 하나가 생성됐다는 이유로 모든 내부 state를 같이 한 칸 전진시킬 필요는 없습니다.

Delayed commitment

같은 구조는 uncertainty를 유지하는 데도 사용할 수 있습니다. 여러 hypothesis가 아직 가능하다면 각각을 evolving state의 서로 다른 component로 남겨 두고, 나중 evidence가 들어왔을 때 중요도를 바꿀 수 있습니다. Continuous vector가 무한한 정보를 담는다는 주장은 필요하지 않습니다. 더 좁은 주장은 discrete token이 특정 quantization과 semantic commitment를 강제하고, 그 결정이 때로는 필요 이상으로 빨리 일어난다는 것입니다.

06 / 세 개의 CLOCK

Token time, compute time, world time은 서로 다르다.

Event가 영향을 받는 state만 갱신할 수 있다면, token counter 하나가 모든 계산의 clock일 필요도 없습니다.

CLOCK 1

Token time

외부 discrete sequence가 visible symbol을 하나 더 내보낼 때 전진합니다.

CLOCK 2

Compute time

Silent recurrent pass를 포함해 internal state가 실제 추가 계산을 수행할 때 전진합니다.

CLOCK 3

World time

관련 있는 외부 event가 발생하면서 전진합니다.

token time != compute time != world time

Null-token recurrence는 이 차이를 직접 드러냅니다. Visible token time은 멈춰 있는 동안에도 compute time은 여러 step 전진할 수 있습니다. 동시에 vision, audio, tool event는 둘과 무관하게 world time에 따라 들어올 수 있습니다.

Event time에도 재현 가능한 순서가 필요합니다. 한 event가 다른 event에 인과적으로 영향을 줄 수 있다면 그 선후는 반드시 보존해야 합니다. 두 event 사이에 인과관계가 없다면 보편적인 선후는 없습니다. 대신 어떤 observer와 reference frame의 chronology인지 명시해야 합니다.

Proper time인가, coordinate time인가?Proper time은 한 observer의 worldline 위에서 local receipt event를 정렬할 때 쓸 수 있습니다. 서로 다른 위치에서 발생한 remote event의 순서를 proper time만으로 정할 수는 없습니다. 그때는 선택한 reference frame의 coordinate time이 필요합니다. 실제 event bus는 frame-relative occurrence time, local receipt time, stable event ID 순서로 정렬하되, chronological order를 causation으로 해석하지 않아야 합니다.

Perceiver IOShared latent representation이 heterogeneous input과 output을 연결할 수 있음.State를 event 사이에서도 유지하고 시간에 따라 필요한 부분만 selective update할 수 있는가?
Hybrid Latent Reasoning via RLRL로 latent와 discrete reasoning 사이의 policy를 최적화할 수 있음.Outcome-driven training으로 언제 silent step을 emit할지, latent를 얼마나 넘길지, 어떤 persistent component를 갱신할지 함께 학습할 수 있는가?
Parallel latent test-time scaling여러 continuous reasoning trajectory를 sampling하고 비교할 수 있음.Parallel component가 별개의 answer rollout이 아니라 entity, goal, sensor process, hypothesis처럼 하나의 world state 내부 요소가 될 수 있는가?
Multi-Stream LLMs여러 token stream을 동시에 read/write할 수 있음.Internal stream이 꼭 token이어야 하는가? 모든 stream이 같은 update clock을 가져야 하는가?
Looped / recurrent-depth TransformersShared transformer block을 반복 적용하면 effective depth를 늘리고 implicit reasoning이나 depth extrapolation을 얻을 수 있음.별도의 recurrent stack을 노출하지 않고 autoregressive null action으로 recurrence를 제어하며 persistent multi-stream state와 결합할 수 있는가?

그래서 주장은 의도적으로 좁습니다.

범용 지능은 relevant event에 의해 비동기적으로 갱신되는 persistent하고 structured한 latent state component 집합을 유지하고, 추가 계산이 필요할 때 silent continuous recurrence를 수행하며, interface가 요구할 때까지 serialization을 미루는 구조에서 이득을 얻을 수 있다.
08 / FALSIFIABLE TESTS

크게 만들기 전에 먼저 깨뜨려 본다.

첫 실험은 architecture 차이가 보이고 compute를 맞출 수 있을 만큼 작아야 합니다.

text CoT | fixed recurrent depth | variable NULL recurrence | asynchronous multi-stream latent
Matched-compute null-token recurrence

Explicit CoT, fixed tied recurrent pass, learned variable null-token pass를 비교합니다. Total transformer FLOPs를 맞추고 task accuracy, latency, visible token 수, silent step 수를 측정합니다.

Gate ablation

Token-only input, null embedding only, ungated latent carry, gated latent carry, always-on gated carry를 비교합니다. Continuous vector가 단순 extra depth가 아니라 실제 유용한 state를 운반하는지 확인합니다.

Monitorability probe

Silent state에서 intermediate reasoning concept를 복원하는 probe 또는 auxiliary decoder를 학습합니다. Null-step budget이 늘수록 decodability가 어떻게 변하는지, explicit CoT checkpoint를 간헐적으로 넣으면 모든 계산을 text로 강제하지 않고도 oversight를 유지할 수 있는지 측정합니다.

Asynchronous multi-entity world

여러 entity가 서로 다른 schedule로 변합니다. 독립적으로 변화하는 entity 수가 늘어날 때 tracking accuracy, cross-state interference, FLOPs, memory, latency를 측정합니다.

Delayed evidence

초기 observation은 여러 hypothesis를 지지하고, 뒤의 evidence가 이를 판별합니다. Contradiction 이후 revision cost와 recovery를 측정합니다.

Interruption

모델이 말하거나 행동하는 도중 새로운 정보가 들어옵니다. Reaction latency와 기존 continuous computation을 얼마나 재사용하는지 측정합니다.

Cross-modal action without text

Vision과 audio를 입력하고 non-linguistic action을 요구합니다. 중간 text serialization이 실제 가치를 더하는지, 아니면 latency만 만드는지 비교합니다.

Killer ablationCompute를 맞췄을 때 variable null-token recurrence가 explicit CoT + fixed-depth baseline보다 나아지지 않거나 latent carry를 제거해도 성능 손실이 없다면 이 mechanism은 정당화되지 않습니다. Independent clock과 interruption task에서도 asynchronous structured state가 더 단순한 baseline을 이기지 못한다면 broader architecture 역시 정당화되지 않습니다.
